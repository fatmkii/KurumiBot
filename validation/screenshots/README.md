# 久留美素材复核工作台

当前流程：全量自动识别 → 人工复核裁剪框与说话人 → OCR 与简繁转换 → 情绪／台词含义／场景说明 → 导出建库。

## 启动

Python 3.12 和依赖使用 uv 管理。在项目根目录运行：

```bash
UV_CACHE_DIR=/tmp/kurumibot-uv-cache uv run --project validation/screenshots python validation/screenshots/editor_server.py
```

打开 <http://127.0.0.1:8767/editor/>。默认端口为 8767；需要其他端口时使用 `--port`。服务只监听本机。模型凭据读取根目录 `.env` 中的 `DEEPSEEK_API_KEY`，不会写入报告或日志。

原始漫画直接从 `comics/` 的六卷 ZIP 读取，共 920 个图像文件，包含封面等需人工排除的页面。当前全量识别已完成，得到 1,083 条自动候选；候选仍需要逐页人工检查。

## 全量复核与处理

1. 左侧原图占桌面宽度 60%，默认“适合页面”。点击框选择，拖动框移动，拖动四角调整；可画框追加、删除和撤销。支持“适合高度”“适合宽度”和百分比缩放；切页或调整窗口后自动适配。
2. 检查框是否包含可辨人物与完整气泡，删除错误素材。点击“保存并完成本页框体复核”即确认本页所有保留素材的说话人与裁剪框，无需逐条勾选；保存成功后自动进入当前筛选范围的下一页，最后一页保存后停留。保存失败时不跳页。台词可以暂空。无素材页面删除全部框后也需完成复核。也可单独勾选某条“裁剪框已复核”并保存草稿，让该条先进入批量处理。
3. 点击“一键补齐已复核素材”：仅处理已保存、框与说话人已确认的素材，顺序为裁剪图 OCR → OpenCC 繁转简 → 根据图片及台词生成情绪标签、含义与适用场景。成功步骤下次跳过，失败步骤可以重试，不需要等全书复核完成。
4. 右侧可逐条识别台词、生成说明、查看 OCR 原始识别、人工编辑并确认。画框或拖动不会调用模型；点击“识别当前框台词”会自动确认当前素材的说话人与裁剪框，其他素材状态保持原样；单条处理按钮会先保存本页未保存修改，保存失败时不启动识别。完整繁体台词按漫画阅读顺序填写，同格多个属于久留美的气泡合为一条。
5. “素材状态清单”显示全部自动候选与人工新增素材的框体、OCR、标签、含义及场景完成情况。支持筛选待处理、失败、信息齐全素材，点击素材按钮跳转。
6. “生成报告与素材清单”保存修正报告、全部框已复核素材清单和信息齐全清单，用于下一轮建库。

未保存修改缓存于当前浏览器，切页后可以恢复；保存到项目后可在其他浏览器或重启后继续。保存从原图生成 PNG，并保留逐页 JSON 和各修正版本，不修改原漫画。

## 状态与人工内容保护

- 框体复核、OCR、说明各自记录状态。AI 已识别／已生成与人工已确认分别显示，“信息齐全”不代表结果已经全部真人验收。
- OCR 存疑时标记“待人工确认”，暂不生成说明；修正台词后可点击“确认台词准确”。OCR 仍可能漏字或误识别标点。
- 人工修改的台词不会被 OCR 覆盖，新识别内容保留在“最新 OCR 原始识别”中对照。人工填写的标签和说明会保留，批量操作只补空缺。
- 修改框会清除框体确认，并将 OCR／说明标为待更新；修改台词会使已有说明待更新。保留的人工说明需重新确认，批量任务不会擅自重写。
- 浏览器草稿与正在处理的 API 结果通过版本检查保护，避免旧结果覆盖新修改。

关闭浏览器不会中断服务端任务。关闭服务或重启电脑会中断，重新启动后点击批量按钮续跑。认证、余额等不可重试错误会停止整批任务；单个网络或输出错误记录为失败并继续其他素材。

## 自动识别

先定位人物、分镜与逐个气泡，再独立复核身份、说话人、完整性和遗漏；最终框覆盖分镜、人物和全部相关气泡的范围并集，并增加边距。保留明确内心独白，排除纯叫声。使用两张久留美正参考及三张真人判错的角色反例。

页面上的“继续全量自动识别”可恢复任务。成功页面、已完成人工整页复核页面自动跳过，后到达的自动结果不会覆盖人工修正。并发为 2；每个阶段最多两次尝试，每次超时 120 秒。

命令行处理全部页面，避免与工作台同时启动：

```bash
UV_CACHE_DIR=/tmp/kurumibot-uv-cache uv run --project validation/screenshots python validation/screenshots/auto_v2.py
```

## 保留的数据与资源

| 路径 | 用途 |
| --- | --- |
| `artifacts/all_pages.json` | 920 页来源清单 |
| `artifacts/round2/pages/` | 全量识别状态、响应与候选 |
| `artifacts/round2/history/` | 自动识别重试历史 |
| `corrections/pages/` | 当前人工复核与处理记录 |
| `corrections/history/`、`corrections/crops/` | 修正快照与原图裁剪 PNG |
| `corrections/enrichment_job.json` | 批量素材处理进度 |
| `corrections/corrected_catalog.json` | 已完成整页框体复核素材及处理状态，可能仍有未处理项 |
| `corrections/ready_catalog.json` | 上述页面中图片、繁简台词、标签和说明齐全的素材 |
| `corrections/人工修正报告.md` | 修正数量及待复核页面报告 |
| `human-review/` | 既有真人复核记录、收录规则与意见，保留用于对照 |
| `references/` | 当前自动识别使用的三个角色反例 |
| `作品与角色背景.md` | 每次生成说明时发送的共同背景 |
| `volume-context/01.md` 至 `06.md` | 按素材卷号注入的对应卷背景，保留核对来源 |

仅确认了单条框的草稿可以先处理，完成整页框体复核后才进入正式导出。未识别或零候选页面仍需通过页面清单全面复核。

背景取自官方作品、角色与卷简介的中文摘要，不是逐页剧情。图片和确认台词优先，不能强行套用交易情境。编辑背景后，下次生成读取新版；已生成说明不会自动重新收费处理。

迁移或备份工作台时，应保留原漫画、`pics_sample/`、`references/`、`artifacts/`、`corrections/`、`human-review/` 与 `.env`。漫画派生图片、自动响应及人工处理数据不纳入版本控制，不能仅靠 Git 恢复这些数据。
